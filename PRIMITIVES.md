# Primitives

Location: project root, single package.
Status is `confirmed` or `inferred`; `pending` marks code not yet on the integration branch, with the branch name when one exists.

## model

- **`Lot`**, `src/model/types.ts`, confirmed
  The single reference frame of the plan, with street sides and boundary walls. Contract: `{ width, depth, frontSide, cornerSide (adjacent to frontSide, or null), boundaryWalls: Record<Side, boolean>, sidewalkWidth, northDeg, ground: Fill, frontage }`, integer mm, origin at the lot top-left, x right, y down; `northDeg` is true north, clockwise from screen up; `frontage` is [[PRIMITIVES#Frontage]].
  Consumers: >=5 (FrontageGeometry, ContextGeometry, SunLayer, item select `clampToLotBox`, AreaOps `clampToLot`); planned: LotLayer, WallDerivation, Snapper, export layout, LotWizard, LotInspector.
- **`Frontage`**, `src/model/types.ts`, confirmed
  The sidewalk items on the street sides of the lot. Contract: `{ ramps: SidewalkRamp[], trees: StreetTree[] }`; `SidewalkRamp { id, side, at, width, gateId }`, where `at` is the center along the lot side, `width` includes the flares, and `gateId` is the vehicle gate the ramp follows, null after a manual edit; `StreetTree { id, side, at, size, species }`, where `at` is the trunk along the side and `size` is the canopy diameter. The rules live in [[PRIMITIVES#FrontageGeometry]].
  Consumers: >=3 (FrontageGeometry, ContextGeometry, street-tree and sidewalk-ramp select handlers).
- **`Area`**, `src/model/types.ts`, inferred
  The unit that users draw, name, paint and measure; walls derive from it. Contract: `{ id, kind: 'room' | 'covered' | 'outdoor', preset, name, shape, fill, labelOffset }`; shape is rectilinear integer-mm rings, outer ring with positive signed area; `covered` builds no wall to the outside; `outdoor` never builds walls and is never carved.
  Consumers: ? (planned: WallDerivation, AreaOps, render layers, AreaInspector, paint tool, export).
- **`Opening`**, `src/model/types.ts`, inferred
  A door, window or gate that cuts a host wall, with hinge and swing. Contract: `{ id, type, axis, line, at, width, height, sill, hinge, side }`; the host wall run resolves at derive time; an opening without a host renders red with a warning and is never deleted silently.
  Consumers: ? (planned: WallsLayer, OpeningsLayer, opening tool, OpeningInspector, AreaOps, export).
- **`Item`**, `src/model/types.ts`, inferred
  A free catalog object (furniture, fixture, car, tree, pillar) on its own layer. Contract: `{ id, type, variant, x, y, w, d, rotation, color, label, mirrored }`; enters boolean ops only as its axis-aligned box ([[PRIMITIVES#RectilinearGeometry]]).
  Consumers: ? (planned: ItemsLayer, item tool, Snapper, net area (pillars), label placement, ItemInspector, export).
- **`Ruler`**, `src/model/types.ts`, inferred
  A user-placed fixed measurement. Contract: `{ id, mode: 'free', a, b } | { id, mode: 'fit', origin, axis }`; `fit` re-resolves wall face to wall face on every derive, with house walls and the lot wall as obstacles.
  Consumers: ? (planned: RulersLayer, ruler tool, RulerInspector, plan checks, export).
- **`Units`**, `src/model/units.ts`, inferred
  The integer millimetre policy plus pt-BR format and parse for every label and input. Contract: `toMm, formatLength, formatArea, formatCm, formatOpening, parseMeters, roundMm`; area rounds half up on integer mm²; parse accepts comma and dot.
  Consumers: ? (planned: all labels, MeasureInput, LotWizard, inspectors, export title block).
- **`ProjectCodec`**, `src/model/codec.ts` (+ `migrate.ts`, `schema.ts`), inferred
  The versioned persistence contract for storage, files and share links. Contract: `serializeProject(doc)`, `parseProject(text, { newId }) -> { doc, repairs }` or `CodecError` with a pt-BR `userMessage`; `format: 'casinha.project'`, integer `schemaVersion` with sequential migrations; a newer version is rejected; import always creates a copy.
  Consumers: ? (planned: repository, projectFile, shareLink, templates).

## analytics

- **`track`**, `src/analytics/track.ts` (+ `index.ts`), confirmed
  The only way to send an analytics event. Contract: `track(name, params?)` sends `gtag('event', name, params)` and never throws; names and params are typed in `AnalyticsEvents`. The Google tag in the GTM container (`G-D5GSQGSWEZ`, set in the container, not in the code) forwards every event to GA4 with no GTM tag or variable per event, so a new event or param needs no GTM change. gtag event params do not persist between events, so there is no key list and no undefined padding. `setPage(screen)` sends `gtag('set', { page_location, page_title })` with the origin plus the virtual path of the screen from `PAGES` in `track.ts`, never the real URL, because the `#plan=` hash holds the whole plan; `PAGES` is a `Record<Screen, …>`, so a new `Screen` value does not typecheck until it has a path. `errorCode(message)` hashes a message into a short code, so no user text reaches analytics; `gtag()` is exported for the module's own commands. `startAnalytics()` (`index.ts`, called from `main.tsx`) runs only in production: it calls `setPage` before `gtag('js', new Date())`, so the automatic first `page_view` of the container uses the virtual page; on each later `uiStore.screen` change it calls `setPage` and then `track('page_view')`; it injects gtm.js when the browser is idle. Call sites import from `track.ts`, never `index.ts`, so stores do not import uiStore through it.
  Consumers: 16 import `track.ts` (Toast, ExportDialog, ShareDialog, SettingsDialog, StartScreen, LotWizard, ThemeToggle, shortcuts `commands.activateTool`, docStore undo and redo, sunStore toggle, build, item and opening tools, repository `openProject`, projectFile, shareLink); `index.ts` has 1 (main.tsx).

The only other `docStore.close()` calls are in "Salvar como nova ideia", which opens the copy right after, and the `ToolContext` `doc.close` passthrough (`src/editor/toolContext.ts`), which no tool calls.

## collect

- **`postPlan`**, **`listPlans`** and **`fetchPlanText`**, `src/collect/api.ts` (+ `config.ts`), confirmed
  The HTTP client of [[PRIMITIVES#minha-casinha-plantas]]; the live socket is [[PRIMITIVES#startLive]]. Three places hold the Worker origin: `PLANS_API` in `config.ts`, from which `PLANS_LIVE_URL` derives, and its `https:` and `wss:` entries in `connect-src` of the CSP in `vercel.json`, so an origin change goes into all three. Contract: `postPlan(meta: UploadMeta, body, keepalive) -> UploadResult { status, retryAfterS }` (`retryAfterS` is a readable positive `Retry-After` in seconds, else null) rejects only on a network failure, and sends `text/plain;charset=UTF-8` so the POST stays a simple CORS request with no preflight; `uploadUrl(meta)` builds its query. `listPlans(key) -> RemotePlan[]` is newest first and cleans each entry with `toRemotePlan(v) -> RemotePlan | null`, which drops ids that fail `ID_PATTERN`, gives 0 for an unknown lot size and also cleans the live `plan` event, so a new plan field goes into it once; `fetchPlanText(key, device, project) -> string` is the project JSON text, untrusted until it goes through the codec. The keyed calls (`listPlans`, `fetchPlanText`, [[PRIMITIVES#deletePlan]], [[PRIMITIVES#getUsage]]) send `Authorization: Bearer <key>` with `cache: 'no-store'` and throw `GalleryApiError` with `kind` `unauthorized` (401), `not-found` (404), `server` (other failed status or a bad body) or `network` (no response). `ID_PATTERN` is the device and project id rule; the Worker keeps an identical copy, so a change goes into both.
  Consumers: postPlan 1 (startCollect); listPlans, fetchPlanText and GalleryApiError 1 (GalleryScreen); toRemotePlan 2 (listPlans, startLive); ID_PATTERN 2 (api.ts, startCollect).
- **`getUsage`** and **`recountUsage`**, `src/collect/api.ts`, confirmed
  The owner's view of the Worker quota ([[PRIMITIVES#UsageCounter]]). Contract: `getUsage(key) -> Usage` reads `GET /v1/usage`; `recountUsage(key) -> Usage` calls `POST /v1/usage/recount`, which rebuilds the totals from the stored plans; both are keyed calls with the errors of [[PRIMITIVES#postPlan]]. `Usage { month, writes, writesLimit, bytes, bytesLimit, plans, paused, reason: 'writes' | 'storage' | null }`; `toUsage(data) -> Usage | null` cleans one usage object (a field that is not a finite number becomes 0, an unknown reason becomes null) and also cleans the usage in each live event, so a new usage field goes into it once.
  Consumers: getUsage and recountUsage 1 (GalleryScreen); toUsage 2 (api.ts `readUsage`, startLive).
- **`startLive`**, `src/collect/live.ts` (+ `PLANS_LIVE_URL` in `config.ts`), confirmed
  Keeps one authed live socket to [[PRIMITIVES#UsageCounter]] for the gallery, also while the tab is hidden. Contract: `startLive(key, handlers) -> stop` with `LiveHandlers { onStatus('live' | 'reconnecting'), onUsage(Usage), onPlan(RemotePlan), onDeleted(device, project), onBadKey(), onResync() }`; it connects to `PLANS_LIVE_URL` (`PLANS_API` with `ws` in place of `http`, plus `/v1/live`) and sends the key in the first message, never in the URL. The status is `reconnecting` until `ready`; event entries go through `toRemotePlan` ([[PRIMITIVES#postPlan]]) and `toUsage` ([[PRIMITIVES#getUsage]]). It pings every `PING_MS`, and a missing pong within `PONG_TIMEOUT_MS` counts as a dead socket. Close 4401 stops for good and calls `onBadKey`; 4429 retries after `TOO_MANY_RETRY_MS`; every other close (4408, 1006 and the rest) retries with an exponential backoff with jitter. A socket that comes back after a `ready` calls `onResync`, because events can be missing, so the caller reloads the list. Back on a visible tab, an open socket proves itself with a ping and a dead one reconnects at once. `stop()` closes with 1000 and never reconnects.
  Consumers: 1 (GalleryScreen, while a key is set).
- **`deletePlan`**, `src/collect/api.ts`, confirmed

- **`getGalleryKey`**, `src/collect/galleryKey.ts`, confirmed

Contract: `getGalleryKey() -> string | null`, `setGalleryKey(key)`, `clearGalleryKey()`, `hasGalleryKey()`; in production they work over localStorage `casinha:gallery-key`, where blocked storage reads as no key, and a key that cannot be stored lasts only while GalleryScreen holds it. - **`seenPlans`**, `src/collect/seenPlans.ts`, confirmed
  The owner's read state of the received plans, kept per browser. Contract: `readSeen() -> SeenMap` and `writeSeen(map)` over localStorage `casinha:gallery-seen`, which maps `planId(p)` (`device/project`) to the `updatedAt` of the version the owner last saw; blocked or broken storage reads as nothing seen, and a write that fails lasts only for the screen. `seenStateOf(map, p) -> 'new' | 'updated' | 'seen'`: a plan with no entry is new, and a plan whose `updatedAt` is later than the stored one is updated, so a plan changed after the owner saw it is unread again. - **`startCollect`**, `src/collect/uploader.ts`, confirmed
  Sends a copy of each plan that the user edited to [[PRIMITIVES#minha-casinha-plantas]], in production only, never on the owner's device ([[PRIMITIVES#getGalleryKey]]) and never for a temporary or read-only plan in the editor ([[PRIMITIVES#openTemporary]]). Contract: `startCollect() -> stop`, mounted once by App; it listens to `onDocSaved` and `onUserEdit` ([[PRIMITIVES#onDocSaved]]) and keeps its state in localStorage `casinha:collect` (a random device id, the `since` time, per-plan `edited`, `dirty` and last `sent` hash, and one backoff and one quota pause for all plans), which it reads again at each step because other tabs share it. A plan uploads only when it has a room and counts as edited: `onUserEdit` saw an edit to it, or the plan was created before `since` and its drawing is unlike every template (SHA-256 of the doc without id, name and dates), so an untouched template copy never uploads; a save of an edited plan that is not open, such as a rename on the start screen, also marks it dirty. The body is the gzip of `serializeProject`. Dedupe: the content hash is a sync FNV-1a hash (two 32-bit passes plus the length) of the doc with `updatedAt` blanked, and a plan whose hash equals the last sent one does not upload. The `updated` query value is the later of the stored `updatedAt` and the last edit time of the plan in this tab, so the gallery sees the time of the last edit even before autosave stores it. Throttle: one upload per plan at once; the first goes at once, then at most one per plan per `THROTTLE_MS` (5 min), and the last one in the window sends the latest version. Flush on hide (`visibilitychange` to hidden, `pagehide`): it runs synchronously up to each `fetch`, past the throttle, and sends the dirty plans with `keepalive`, the open plan first; it sends the gzip body prepared `PREPARE_DELAY_MS` after the last edit when that body has the current content, else the plain JSON of the current content (the Worker takes both), else the older gzip body when the JSON does not fit; all bodies share the `KEEPALIVE_MAX_BYTES` budget, under the 64 KB browser limit; a hash that a hide flush already sent in this tab is not sent again, so `pagehide` after `visibilitychange` sends nothing twice. The responses set one shared wait for all plans, which the throttled path, the hide flush and the backfill all respect: a 429 starts the backoff, which doubles up to `BACKOFF_MAX_MS`; a 503 (the quota counter is down) waits `UNAVAILABLE_BACKOFF_MS`, with no doubling; a 507 (the quota is full) pauses until its `Retry-After`, or for `QUOTA_PAUSE_DEFAULT_MS` without one. A success clears the 429 and 503 waits but not the 507 pause. A 429, 503 or 507 stored nothing, so it does not count against the throttle: the next send of that plan waits only for the shared wait. A body over 1 MB, the Worker limit, never uploads; other failures keep the plan dirty for a later save or session. Backfill, `BACKFILL_DELAY_MS` after start: it removes the state of deleted plans and sends the dirty and never-sent plans one at a time, at most `BACKFILL_MAX` per session; a plan inside its throttle window or during the backoff waits for a scheduled upload.
  Consumers: 1 (App).

- **`minha-casinha-plantas`**, `workers/plans/worker.js` (+ `wrangler.toml`), confirmed
  The Cloudflare Worker that stores the collected plans in R2, keeps them inside the R2 free tier and serves them to the gallery. Contract: R2 binding `PLANS` on bucket `minha-casinha-prd`, one object per plan at `plans/<device>/<project>.json`, which each upload overwrites, so only the latest version stays; Durable Object binding `USAGE` ([[PRIMITIVES#UsageCounter]]); it is served on its `workers.dev` origin, which `PLANS_API` holds ([[PRIMITIVES#postPlan]]); `wrangler.toml` is the reference config, and the deploy goes through the Cloudflare API with the same settings. `POST /v1/plans?device&project&name&w&d&updated` takes a gzip body (found by its magic bytes, not by a header) or plain JSON and answers 204; 400 for a bad id, gzip or JSON, or a body without `format: 'casinha.project'` and a numeric `schemaVersion`; 413 over 1 MB raw or 8 MB inflated; 429 past `WRITE_LIMIT`, 30 writes per 60 s per `CF-Connecting-IP`, which applies only while that binding exists. A valid body then reserves the write in the counter, with its inflated size: 507 with `{ error: 'quota', reason: 'writes' | 'storage' }` and `Retry-After` (the seconds to the next UTC month for `writes`, one day for `storage`) when the quota refuses it, and 503 when the counter fails or stays unseeded after one seed; a failed R2 put undoes the reservation. The query becomes cleaned R2 custom metadata; `updated` is the client date clamped to the server time, so a future date cannot pin a plan to the top, and a missing or bad date becomes the server time. `GET /v1/plans` gives `{ plans: [{ device, project, name, lotWidthM, lotDepthM, updatedAt, bytes }] }`, newest first, from the full R2 list, with null for an unknown lot size. `GET /v1/plans/<device>/<project>` gives the stored JSON text, or 404; `DELETE /v1/plans/<device>/<project>` deletes the object, then releases its size in the counter, so a failed release can only leave the total too high, and answers 204 also when the plan is already gone, so a repeat delete succeeds; both answer 400 for a bad id. `GET /v1/usage` gives the counter's `{ month, writes, writesLimit, bytes, bytesLimit, plans, paused, reason }` and seeds the counter first when it is unseeded; `POST /v1/usage/recount` rebuilds the totals from a full R2 listing and gives the same shape. A stored plan, a delete and a recount push the `plan`, `deleted` and `usage` live events. `GET /v1/live` needs `Upgrade: websocket` (else 426) and an `Origin` in `ALLOWED_ORIGINS` (else 403, also with no `Origin`), then hands the socket to the counter, which runs the socket protocol; its 101 response skips the common headers. The plan GET routes, DELETE and both usage routes need `Authorization: Bearer <GALLERY_KEY>`, and the live socket needs the same key in its first message; the key is compared as SHA-256 digests with `timingSafeEqual`, and every keyed route answers 401 while the secret is not set; `GALLERY_KEY` is a Worker secret, never in the repo. CORS headers go only to an `Origin` in `ALLOWED_ORIGINS` (the production app and the local Vite dev server), allow `GET, POST, DELETE, OPTIONS` and expose `Retry-After`; OPTIONS answers 204; every HTTP response carries `Cache-Control: no-store` and `Vary: Origin`.
  Consumers: 3 clients (startCollect through `postPlan`; GalleryScreen through `listPlans`, `fetchPlanText`, `deletePlan`, `getUsage` and `recountUsage`; startLive through `/v1/live`).
- **`UsageCounter`**, `workers/plans/worker.js` (+ `wrangler.toml`), confirmed
  The one Durable Object that holds the R2 quota and the gallery's live sockets. Contract: SQLite class bound as `USAGE` (migration `v1`), one instance (`idFromName('global')`). Quota: `BYTES_LIMIT` (1 GB, decimal) stored and `WRITES_LIMIT` (100,000) successful writes per UTC month, so the bucket stays in the R2 free tier; the write count resets when the month changes, and GalleryScreen's size labels use the same decimal units. It keeps one size entry per object key. `reserve(key, bytes)` counts a write before the R2 put and refuses `writes` at the write limit, or `storage` when the write grows the total past the byte limit, so a write that keeps or shrinks a plan's size still passes at the limit; `undo(key, bytes, previous, month)` reverts a reservation whose put failed and leaves an entry that a later write replaced; `release(key)` removes the size of a deleted plan. `recount(entries, startedAt, onlyIfUnseeded)` replaces the sizes with a full R2 listing, and an entry written after `startedAt` wins, so a write during a recount is not lost; until its first recount (the seed) the counter is unseeded and refuses every reservation. `usage()` gives the totals with `paused` and `reason`. Every counter method body is synchronous, which makes each call atomic against the others, so a new counter method must not await inside its body. Live: `fetch` accepts a hibernatable WebSocket (`ctx.acceptWebSocket`, with the socket state in its attachment, so the object can sleep with sockets open), and the auto-response answers `{"type":"ping"}` with `{"type":"pong"}` without a wake. The first message must be `{ type: 'auth', key }` within `AUTH_TIMEOUT_MS`, which an alarm also enforces: a wrong key, another message, a message that is not JSON or one over `MAX_SOCKET_MESSAGE` closes with 4401, and a late one with 4408; a socket closes with 4429 when `MAX_OPEN_SOCKETS` (20) are already open at accept, or when `MAX_AUTHED_SOCKETS` (10) are already authed at auth. An authed socket gets `{ type: 'ready', usage }`, then the `plan` (the cleaned list entry), `deleted` (`device`, `project`) and `usage` events, each with the current `usage`, and the counter ignores its messages except ping. The Worker pushes an event only when an authed socket listens, and a failed push never fails the write that caused it.
  Consumers: 1 (the Worker routes); clients reach it through [[PRIMITIVES#getUsage]] and [[PRIMITIVES#startLive]].
